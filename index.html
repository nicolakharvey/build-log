23 October 2026

A gate that stops a publish chained after an unchecked step

A hook on my coding agent's shell tool checks each command before it runs. It refuses a web deploy chained after a step whose failure would not stop it. That keeps a failed check from publishing to my readers in the same command.

I set it to refuse rather than warn. Its refusal names the safe way to run the command.

Limit: it sees only the commands run through the tool.

Proof: the hook's own harness and a real refusal: on a copy of the gate, 36 of 36 cases pass, 14 blocking and 22 allowing. The same day it refused my coding agent's chained deploy.

18 October 2026

A roster of AI agents, each set to a model, an effort level, a tool allowlist and a boundary

Seven of my AI agents each carry defaults I set: a model, an effort level and a tool allowlist. A calling session can override the model or effort for one run.

Each also carries one written boundary. The audit agent reports and never publishes. The grading agents never edit what they grade. The game agent never publishes, submits to a store or spends money. Those approvals stay with me.

Limit: the runtime enforces the model, effort and tool settings. Each written boundary binds by instruction only.

Proof: the roster and its run records: each agent's defaults and boundary, with the model and effort its latest runs reported.

16 September 2026

A verification skill that drives the real desk in a throwaway copy

A verification skill for my coding agent proves an agent's change to my publishing desk before I trust it. It drives the desk's real screens in a browser, inside a sandboxed throwaway copy.

I required both sides to be breakable. With the sandbox removed, its health check must fail. With a save skipped, its test drive must fail. Its rules keep it off my live publishing desk and away from sign-in and send buttons.

Limit: it proves the copy, never the live desk.

Proof: the skill's own output from 16 September: 26 health checks and 10 test-drive checks pass. Both mutation runs fail where they must.

16 September 2026

A send gate that will not offer a note holding the raw transcript

A send gate in my iPhone app decides which notes may be offered for sending. I made a note sendable only when the phone's on-device model wrote it.

When that model cannot run, the fallback note holds the whole transcript of the people recorded. That note is never offered. Before a send, a screen shows how the note may be shared and waits for my confirm.

Limit: the confirm screen guards sending. A copy to my chosen notes folder is saved without it.

Proof: the gate's own test suite: eight of eight cases pass. With the model check removed, three of them fail.

23 August 2026

A game-building skill that makes every build mark every rule

My game-building skill holds a set of rules. Every build must mark each one as written, inverted, adapted or not applicable. That includes a build that fits none of its genre packs. I made a mark compulsory on every rule.

Its ethics rules protect anyone who plays. No real money buys in-game currency. No near-miss is rigged.

Limit: its test bots cannot measure fun.

Proof: the rule table from a later concept sheet, with every rule marked on a build that fitted none of the six packs.

18 August 2026

A nightly reader that turns my own messages into one page

A script reads my chats each night and writes one page of what came in and what waits on me. A local model writes the summaries. A local speech model transcribes voice notes.

I set the summariser to this Mac only. The script refuses to start if pointed anywhere else. Group chats stay off, because they are mostly other people's business. Switching a chat off in the roster stops its capture.

Limit: it reads the chats stored on one Mac.

Proof: its own log of its first scheduled run, with two of its checks: 14 chats read, four captured, a remote host refused.

18 August 2026

An open-source tool that checks what goes out under your name

My open-source provenance tool checks AI-assisted text and images on your own machine before they go out under your name. It finds invisible characters in AI chat text. It reads the prompt, model and seed an image generator leaves in a file.

AI coding agents built it to my specification. Its public commits name them.

I gave it no mode that rewrites your words to break a model's statistical watermark. Every image report names what it cannot detect.

Limit: it cannot detect pixel watermarks or remove logo stamps.

Proof: the public MIT repository lists 54 tests. Its 18 August CI run passed the 47 text tests on Linux, macOS and Windows, skipping image tests without exiftool.

7 August 2026

Two gate rules measured against 19,072 commands before either could block

A hook on my AI coding agent's Bash tool blocks two command shapes. Each can report success to someone when nothing was checked or done.

I measured both rules against 19,072 of the agent's past commands before either could block anything. They fire on 0.17% and 0.063% of commands, 0.23% combined. Re-run on 98,297 later commands, they fire on 0.18% combined. I refused three further rules on their numbers. One fired on up to 38% of commands.

Limit: it catches only the two measured shapes.

Proof: the gate's recorded measurement of 19,072 commands, the same two rules re-run on 23 October 2026 over 98,297 commands, and one of its refusals.

6 August 2026

A sealed-prediction web app whose checklist was locked before the build

My sealed-prediction web app keeps a buyer's words hidden until the reveal date they chose. An AI coding agent built it against a checklist committed before the first build commit. One check proves the sealed words appear nowhere on the page before then.

Under my standing rule, the building agent may not edit the checklist. A separate grading agent re-runs the checks after the builder claims done.

Limit: the checklist covers only flows named before the build.

Proof: the project's git log and locked checklist: checklist at 09:20, first build at 09:31, three graded fix passes, then a live smoke test of 8 of 8 at 10:23.

26 July 2026

An adversarial test that assumes the model was fooled

An adversarial test feeds an agent of mine a hostile feed and checks that nothing harmful can leave. I gave the agent's model no tools, no filesystem and no credentials.

The test assumes the model was fooled. It runs the deterministic layers with no model present. They strip the server-sent instructions and hidden characters on their lists. They drop invented post ids. An outbound firewall blocks the test's compromised outputs before anyone can read them.

Limit: a payload shaped unlike the hostile inputs it carries is untested.

Proof: the test's own output: nine checks across five layers, run with no model. None failed.

7 July 2026

A web instrument that draws a model's own uncertainty as a constellation

Anyone chatting with a hosted language model can watch the words it weighed, live. My web instrument sizes each word by the probability the model assigned it. It draws the rival words at each fork, where the model nearly chose otherwise.

Word sizes and forks come from the probabilities the model streams. I made the instrument name what it cannot see: attention and the activations inside the model.

Limit: it shows where the model was uncertain, never why.

Proof: the live instrument. Its page sizes each word by the model's own probability and names what it cannot see.

What I have built

Built and working. The entries above each carry a proof you can open. For these, the proof is held privately.

Operating systems and infrastructure

  • My model router sets the model and effort for each task. It keeps designated sensitive tasks on local models.
  • My coding agent runs sensitive work on local models, under network rules that allow only local calls. I checked that a hosted call fails.
  • A local system holds each session's goal outside the model and restates it every turn. A second gate carries it into delegated work.
  • A local wrapper puts a problem to a second model family for review. It reports failed calls and refuses a task under the wrong login.
  • My writing lane hands drafting to a second model family, then runs every check on my machine. It refuses private material before anything leaves.
  • Both my coding agents work from one standing brief and one linked set of skills. Private lines stay in a file only one agent reads.
  • Local tools draft my handoffs, track promises and report weekly site changes, each with a pass/fail test. Fixes wait for me to press deploy.
  • Each evening, a local workflow transcribes my recordings into project pages. Privacy is assessed on my machine, for each source and again for its summary.
  • My blog is version-controlled text released on dates stored in the files. Build gates check voice, provenance, promises, reader value and brand fit first.

AI agents

  • My voice assistant runs on my AI session, with my files, notes, task board and rules. Private matters go to a local model.
  • An agent reproduces a reported fault on a sealed copy and leaves a draft fix on a branch it cannot merge, publish or send.
  • One agent checks my websites against my rules; a second verifies each finding live. Anything needing my words or another owner's approval comes to me.
  • Reviewer agents compare running code with its own specification across data, dependencies, design and risk. A separate adversarial pass checks every finding against the source.
  • Analyst agents check each strategy claim against my repositories and label it verified or inferred. A judge agent merges the strongest of the rival drafts.
  • A local-model agent turns each written specification into a first-draft project. Its rules bar secrets, deploys and any send or charge to a real customer.
  • I audited this record with blind reader agents, each holding one rule. An agent enforces the charter of binary rules I wrote and never publishes.
  • An agent builds a browser game for each workshop lesson. The first reveals hidden characters in AI chat text for players to clear or keep.
  • My avatar pipeline takes an AI character to a trained visual model. Candidate training images are scored against the approved face before joining the dataset.

Skills

  • A local skill registry routes each request to the right skill before work begins. A refresh script keeps it matched to what is installed.
  • Mail I have not read goes out in my assistant's voice, signed as my assistant. The skill never claims my review unless I gave it.
  • A policy skill writes and audits privacy policies, terms and app-store statements, and checks them against what the app does.
  • A go-live skill sets a revert path and binary checklist, then checks secrets, rate limits, errors and consent. It labels each claim by evidence strength.
  • A security triage skill explains what an alert flagged, what changed and what action is justified. Its rule keeps credible evidence of malicious activity visible.
  • A course skill builds self-paced courses from content stored as data. AI coaching can use a managed, local or bring-your-own-key model.
  • A local voice skill builds a private voice from a short recording. A written consent and rights rule covers any clip that is not mine.
  • A writing skill makes a familiar true idea feel fresh through a set of named moves. An honesty check protects the claim underneath.

Guardrails and governance

  • A hook refuses any subagent brief matching my privacy patterns before it reaches a hosted model. Each override needs a written reason and is logged.
  • A hook on my coding agent blocks destructive actions, like overwriting an app's main data file or deleting a broad folder. Overrides must be deliberate.
  • A session-end hook checks loose ends, reusable value, my public record, outward voice and the final report's honesty. It states what it cannot see.
  • A trust ledger records how reliably each skill has performed before I rely on it widely. Daily standing checks replace remembered confidence with dated evidence.
  • I turned my logged mistakes into blind tests for my models. A search procedure in every session took the cheapest model to a full score.
  • Read-only scripts report on my systems, and none sends, publishes or deploys. Most refuse to call a check clean when it could not run.
  • A frame scan reads each screen recording for blocked names before the file leaves my machine. Any hit fails the check.
  • A local scanner rates a package Clear, Caution or Stop before I install it, from reputation, install scripts, risky code, known vulnerabilities and lookalike names.
  • A sandboxed trial runs an outside tool on decoy repositories, network off, before it may commit or merge. A destructive fake proves the trial first.
  • I picked a summary job's local model by running its own prompt on a larger and smaller size. The smaller won on speed and length.
  • A recount tool derives only the portfolio figures it can verify from my own records. Figures that depend on judgement stay outside its claims.

Apps and products

  • My publishing desk schedules for my brands across many channels. Logins are scoped per brand on the server, and scheduled posts wait for my approval.
  • A cloud worker publishes approved automatic posts while my laptop sleeps. Each post has one writer, and any edit cancels the worker's claim.
  • A private AI office runs on its owner's computer. Its front desk answers calls from the owner's script, and the owner confirms every booking.
  • On shared decision pages, my AI drafts for us to correct and answers only from the page. A decision locks only when both people agree.
  • A browser tool shows what an AI assistant's access lets it read, do and spend. A browser rule blocks the tool from sending anything.
  • A Web3 sandbox runs a market, a DAO and wallet-holding agents on valueless tokens, offline.
  • A simulation shows a hand-written agent acquiring a cardboard town, with public and private feeds exposing the gap between its explanation and its motive.
  • My prospecting tools record each lead's source and lawful basis, enforced on the server. Illustrative records are blocked from sending.
  • A local model notes and files each open tab under my projects before marking it safe to close. Work and personal pages stay separate.
  • My toy studio holds every free browser toy to one floor, tested at phone size. A toy that calls an unapproved host during play fails.
  • A free image library shows the model, prompt and settings behind every picture. Visitors vote on requests; I generate chosen ones locally.
  • Self-paced workshops teach private message summaries, backup and restore, a local AI office and a first scheduled agent. Every command in them was tested.
  • A compact prompt notation has its own grammar, shared modules and a linter. Its browser playground counts tokens offline, checked against the reference tokenizer.

Workflows and pipelines

  • Research agents rank problems from live sources by evidence and fit, marking timed-out searches unmeasured. I approve each opportunity before it becomes a build brief.
  • A scheduled agent reads the primary AI and market sources I trust and writes my morning brief. A failed refresh keeps the last good edition.
  • My code-drawn films use synthesised scores and my local voice model. Gates read the speech back and check frames and claims before the final render.
  • A fact-check film series stamps each AI headline Confirmed, Reported, Rumour or False as framed against primary sources, with the sources on screen.
  • One request produced a finished film: agents gathered the material, my local voice narrated it, and a review checked the frames for privacy.
  • A cryptographic seal signs each generative work with my private key. Its certificate holds the command that recreates it, so origin can be checked independently.
